# Desktop storage paths

The native wrapper treats packaged resources as immutable application files. The prepared resource tree contains the typed frontend, backend source, Node runtime, model manifest, and declared runtime packages, including the platform-specific `node-pty` prebuild. It does not stage model weights or a model runtime executable.

At launch, the wrapper creates the writable Covert workspace below Tauri's per-user local application data directory. For this identifier, Windows resolves the Tauri base to `%LOCALAPPDATA%\org.ferrellsyntheticintelligence.aide`; the workspace and `.aide` state are under its `workspace` child. The credential store is `workspace\.aide\credentials.dpapi`, and application logs are under `workspace\.aide\logs`. A Windows dogfood install created the workspace and log directory at these paths outside the installer directory. The credential file was absent because pairing was not performed. This verifies the current account's launch paths, not restart persistence or other accounts; see the evidence report for the exact installed run.

Model storage is a separate path. Set AIDE_MODEL_DIR to an absolute path before launching Covert to choose it. On Windows, when E: exists and the variable is unset, the app uses `E:\CovertData\CovertCoder\models`, with runtime files under its `runtime` child and the default executable at `runtime\llama-server.exe`. If E: is unavailable and no override is set, startup returns an explicit error instructing the operator to set AIDE_MODEL_DIR; model storage is not silently redirected to the per-user application data directory on C:. The selected directory is created if missing.

Model runtimes are external too. AIDE_RUNTIME_DIR selects their directory and defaults to the model directory's runtime subdirectory. AIDE_LLAMA_SERVER can select a specific absolute llama-server executable path. The wrapper rejects state, model, and runtime paths that point into installed application resources.

The current backend still has one AIDE_WORKSPACE root for both workspace files and .aide state. The desktop wrapper points that root at its per-user workspace. This package branch does not yet provide a canonical Project Registry or mount an arbitrary existing project at its real path. Until that service integration exists, do not describe this candidate as supporting real-project mounting or as having fully separated project files from Covert state.
