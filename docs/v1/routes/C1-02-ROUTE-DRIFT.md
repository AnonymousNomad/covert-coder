## Canonical ownership and route identity

- Typed route definitions: node/src/openapi.ts buildRoutes() constructs typed route definitions; node/src/server.ts registers and dispatches these definitions.
- OpenAPI: generateOpenApi() in node/src/openapi.ts derives common/openapi.json from every non-raw typed route; tests/arch/openapi-drift.test.ts enforces generation parity.
- Facade: common/facade-route-map.json is consumed by scripts/facade.mjs; exact path wins, then longest segment prefix wins, then dispatch defaults to legacy.
- Map generation: scripts/build-facade-map.mjs derives family prefixes from OpenAPI path strings and source regexes over daemon/server.mjs; it preserves only path-level target keys, not HTTP method identity.
- Legacy implementation: daemon/server.mjs handleLegacy() branches implement the legacy endpoint conditions inventoried below.
- Authority: Typed server route authority is verified by tests/arch/route-authority-coverage.test.ts; that test checks dispositions and that facade-to-TS mappings point at some typed route path, but does not assert every registered method/path targets the typed server.

The operation identity used here is HTTP method plus canonical path, retaining the /api prefix and route-template spelling. OpenAPI operations and typed registrations share the route path string. The facade canonicalizes a request to its decoded pathname and currently selects an upstream by path only. HTTP method does not participate in target selection.
