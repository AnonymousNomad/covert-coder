# Workstation implementation baseline

Status: authorized direction formalized for staged implementation; reconciliation/runtime acceptance open. No final build/design acceptance claimed.

## Product and ownership

Personal developer platform through a desktop inside Windows. Relationships: Desktop / Projects / Applications and Tools / Intelligence Resources / Platform Services. Windows remains the host OS.

One existing Tauri host/WebView, bounded internal frame manager, existing vanilla TypeScript/DOM, store and typed API client. No new UI framework, daemon, VM/container abstraction or universal capability database.

Frame manager owns geometry/focus/visibility/layout only. Backend owners retain roots, processes/tasks, grants, credentials, model/runtime/admission and verification. Human/Cipher/worker requests share canonical operations with distinct principals/scopes.

Many known projects; one foreground governed project in V1. Bind every view/task to ProjectID plus explicit root/checkout revision. Project switches cannot retarget pending grants/proposals, background tasks or evidence.

## Visual and interaction

Keep reference near-black/phosphor-green, dense technical character, opaque rectangles, thin borders, compact title bars, sparse shortcuts, top system strip, central work area and bottom running-task strip. Compact telemetry edge is collapsible on narrow hosts. No cards, glass, chat-first rail or expensive decorative background.

Candidate tokens: desktop #060807, window #0C110D, inset #131B15, text #96DAA1, phosphor #86F59B, muted text #669871, border #314A37, focus #B0FFC1. Validate against each actual surface. Initial text 13–14 CSS px with scaling. Approximate 26–30px title bars; accessible targets, labels/icons independent of color. Syntax/semantic colors remain purposeful.

Original static Covert Visor: asymmetric bracket/offset interrupted slit, sparse segmented technical contours. No recognizable reference logo/mask. Companion families echo optical construction but retain separate outlines.

Rehost editor/files/search, terminal, Git, models, connections, workflows, verification, monitor/settings. Preserve old controls until equivalent behavior and failures have proof. Missing features show actual unavailability.

Launcher searches existing apps/commands/projects/capabilities, distinguishing installed from catalog and usable from unavailable. Profiles reference layout/tools/terminal/model roles/workflow preferences; applying never silently installs/downloads/executes/grants/routes data.

Beginner/Standard/Expert alter disclosure, never capabilities or enforcement. Decisions retain scope/egress/failures in every mode.

## State truth

Installed/configured/authenticated/reachable/available/qualified/selected/authorized/admitted/running/verified remain distinct facts, with independent freshness. Disabled/revoked/degraded have owner-specific meaning. Unknown/stale telemetry is not zero/healthy.

Projection uses source identity/scope/time/revision where supplied. Do not fabricate sampling timestamps or universal READY. Late prior-project/generation responses cannot overwrite current scope.

Model Manager/access owns model truths; Broker/Admission owns load/resource decisions; Connections owns eligibility; protected stores own credentials; Authority owns grants; Veritas owns source-bound evidence; existing journals own tasks/history; Resident binding owns Cipher identity. UI owns presentation preferences only.

Backend services surface when an operation needs attention: exact proposal/permission/denial, resource required vs observed, source-bound verification gates, artifact trust, egress destination. Recommendations never silently act. A process exit zero is not a verification pass.

## Recovery

Tools remain usable when AI is unavailable within their own dependencies. Do not mistake whole-daemon loss for AI-only failure. Show truthful route-specific reasons.

Persist per-project layout, tabs/view state, approved preferences and buffers through their existing owners. Restore presentation intent then reconcile runtime. Never restore live process, model RUNNING, provider reachability, fresh approval, current verification or active capture from layout data.

Use existing task/event/evidence journals with UI projections. Do not fabricate durable history where backend integration is missing.
