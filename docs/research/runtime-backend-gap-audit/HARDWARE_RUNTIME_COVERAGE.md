“Supports Linux” or “supports Windows” is not enough for a matrix claim. Covert still needs pinned package, architecture, runtime/provider and hardware profile acceptance.

The OS columns describe the documented host/runtime route, not merely the availability of a Docker image. Container packaging does not expand host support by itself: a Linux container on Windows remains a WSL2/Linux-host profile, with separate driver/device passthrough, process ownership and shutdown evidence. The sources reviewed did not justify classifying any runtime as *container-only* across all OSes; vLLM, SGLang and TensorRT-LLM often use container deployment, but their Linux and hardware floors remain the governing support boundary.

## OS/platform distinctions that must remain visible in product

- **Native Windows** and **WSL2** are different supported profiles. A Linux runtime reached from WSL is not native Windows support.
- **Container support** still depends on host drivers, device passthrough, container runtime and runtime image. It is not a host-native adapter unless Covert owns and qualifies the container path.
- **Windows ARM64** is not Windows x64; Python/native wheels, QNN packages, and model graphs have their own ABI/driver gates. Do not infer Windows ARM64 from a JVM API that only says “Windows.”
- **macOS Intel** is not Apple Silicon. MLX support cannot be inferred for Intel Macs.
- “Runs on CPU” is not enough to describe low-RAM machines; expose fit/latency constraints and `UNKNOWN` cache estimates honestly.

## Practical coverage conclusion

For beta-scale broad local coverage, qualify at least one llama.cpp profile per major backend family (CPU, NVIDIA CUDA, modern AMD HIP, Windows/Linux Vulkan, Apple Metal, Intel SYCL only if supported target demand exists). Then add ORT GenAI package profiles for Qualcomm QNN / Windows ARM64 and AMD Ryzen AI VitisAI / Windows x64 as demand and physical acceptance hardware permit; evaluate DirectML/OpenVINO under separate profile IDs. LiteRT-LM, ExecuTorch, and MNN-LLM belong to a separately scoped mobile/edge lane. This is narrower and more governable than a large catalog of engines, while preventing the current NVIDIA-on-Windows probe from deciding what hardware Covert claims to see.
