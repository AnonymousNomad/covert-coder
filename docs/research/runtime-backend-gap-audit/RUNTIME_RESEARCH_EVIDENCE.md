### Serving, lifecycle and observability capabilities

The capability columns in the CSV describe the upstream engine/library at the pinned revision. For artifact columns, `SUPPORTED` means a documented direct runtime package path, `PARTIAL` means conversion/plugin/profile-constrained use, and `UNKNOWN` means the inspected sources did not establish the format. `PARTIAL` for lifecycle can mean process-level load/unload, a feature limited to one API/backend, or reporting only some relevant counters. `resource_vram_reporting` means runtime-reported resource/cache metrics exist; it does **not** substitute for Covert's sourced host GPU/VRAM telemetry or prove that the expected accelerator executed. `chat_completions` is a chat generation workflow; `openai_api` is a separate HTTP API compatibility claim.

- [llama.cpp server guide](https://github.com/ggml-org/llama.cpp/blob/11fe02151f79c41d0d4af7da708755d73b9c0da6/tools/server/README.md): server/router operation, OpenAI-shaped endpoints, optional `/metrics` and slots monitoring, model routing/load/unload controls. API/metrics are optional/configuration-dependent; cancellation and runtime identity still need profile tests.
- [vLLM OpenAI-compatible server](https://github.com/vllm-project/vllm/blob/6f75cc7d5d1b5adfb399cbf79a8231ae66844fcf/docs/serving/online_serving/openai_compatible_server.md) and [metrics](https://github.com/vllm-project/vllm/blob/6f75cc7d5d1b5adfb399cbf79a8231ae66844fcf/docs/usage/metrics.md): chat/server routes, request lifecycle, Prometheus generation and cache metrics. Do not treat cache metrics as universal raw VRAM accounting.
- [SGLang OpenAI API](https://github.com/sgl-project/sglang/blob/1315d171a012b28a1d676e0abaa6124750252a57/docs/docs/basic_usage/openai_api.mdx) and [production metrics](https://github.com/sgl-project/sglang/blob/1315d171a012b28a1d676e0abaa6124750252a57/docs/docs/references/production_metrics.mdx): server chat/stream APIs and token/GPU performance metrics. Its [server argument docs](https://github.com/sgl-project/sglang/blob/1315d171a012b28a1d676e0abaa6124750252a57/docs/docs/advanced_features/server_arguments.mdx) restrict background-response cancellation to enabled/stored requests; that does not prove cancellation of every active stream.
- [ORT GenAI API examples](https://github.com/microsoft/onnxruntime-genai/blob/24b310ade7bff608067e7a9709d60a51e17aed91/examples/python/README.md) provide token streaming, multimodal generation, tool and constrained-format examples; the runtime is a library rather than an OpenAI-compatible server. Current C API docs describe cancellation semantics, but a specification/API contract is not by itself proof of the packaged runtime or a Covert integration, so the matrix leaves cancellation `UNKNOWN` pending an implementation and test binding.
- [ExecuTorch LLM server](https://github.com/pytorch/executorch/blob/903cef0637741a47138536080ec053f933828a67/examples/llm_server/README.md) explicitly lists streaming, bounded cancellation and a narrow chat API; it also rejects unsupported request parameters and is labeled experimental.
- [LiteRT-LM Conversation API](https://github.com/google-ai-edge/LiteRT-LM/blob/d17a52fd5c2b4ce1280959309af175caebaac2c3/docs/api/cpp/conversation.md) and [Kotlin engine lifecycle](https://github.com/google-ai-edge/LiteRT-LM/blob/d17a52fd5c2b4ce1280959309af175caebaac2c3/docs/api/kotlin/getting_started.md) document streaming conversation/tool APIs and explicit engine close. The reviewed API pages do not establish request cancellation, live context utilization or VRAM counters.

## LocalAI architecture comparison

LocalAI’s official docs show a core service coordinating backend processes, a configurable backend/model gallery, backend variants and hardware-targeted packaging. Its hardware/runtime discovery and image/variant hints are useful for producing candidates, but remain availability hints rather than exact Covert qualification. Useful separations to keep are: backend is explicit model configuration; runtime package variants are tied to hardware; model/backend compatibility is declared; model files can carry expected hashes; and backend install/discovery is distinct from model install. Do not inherit automatic alias selection or turn its large multi-process backend gallery into Covert’s authority/lifecycle layer.

Covert should reuse those principles in its existing Runtime Adapter/Model Access architecture: small explicit runtime registry, machine-readable compatibility, pinned variant/digest, package manifest, and separate runtime/model lifecycle. It should not import LocalAI’s broad gallery/dependency graph or treat automatic hardware aliases as qualification. Covert has stricter Authority, Local-Only, endpoint ownership, cancellation and audit requirements that must remain first-party.
