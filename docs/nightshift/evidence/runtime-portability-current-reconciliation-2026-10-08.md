### Answer to the intake question

Another adapter can be added at the broker/adapter layer without replacing canonical model IDs or artifact-source ownership. A third adapter cannot yet be **independently qualified, admitted, and represented truthfully** without additive profile, qualification, admission, and Model Manager contract work. Therefore the architecture is extension-ready at the execution seam but not yet portable at the qualification seam.

## Minimum change required before qualifying another runtime profile

This is the smallest design boundary supported by current source; it is not authorization to implement an abstract runtime platform now.

1. **Strict profile catalog.** Add a small, versioned allowlist of immutable profile IDs. A profile must distinguish runtime family/build and relevant accelerator/backend combinations; e.g. CPU, Vulkan, and ROCm cannot share a qualification merely because all use llama.cpp. Reject unknown profile IDs. Do not accept arbitrary runtime names or plugin discovery as product authority.
2. **Portable, evidence-bound passport.** Add a versioned qualification record that binds the profile ID; runtime executable/library build digest and version; OS/build and native/WSL/container execution environment; observed device/vendor/architecture/driver; exact model artifact hash and source lineage; digest of runtime-affecting template/context/parameters; required capability claims; admission policy and sourced measurements; and an immutable evidence-set digest with freshness/staleness rules. Unknown fields stay UNKNOWN and invalidate any claim that depends on them.
3. **Profile-aware admission.** Resolve start requirements from the exact selected profile while retaining the existing Unsloth V1 floors and refusal behavior. Require each profile to state which physical/commit/VRAM/accelerator measurements it needs and how they are sourced. Missing required measurements refuse start; there is no floor bypass or automatic fallback.
4. **Existing Model Manager projection.** Preserve canonical model identity, artifact source, provider route, selection, Authority, and readiness state owners. Add only enough runtime-profile identity to report which exact profile is configured/observed and whether evidence matches it. Selection is not qualification; a started listener is not a qualified model.
5. **Migration and invalidation proof.** Keep V1 Unsloth passport content and scope unchanged. Add tests proving its exact existing tuple still matches, while a changed runtime build, backend/profile, host/device/driver, artifact, relevant configuration, or required capability invalidates dependent claims. Test UNKNOWN, stale evidence, no silent fallback, and profile mismatch.

The existing V1 Unsloth passport is narrowly scoped and contains UNKNOWN values for fields its qualified API did not expose. The portable record must preserve those limitations; it must not retroactively fabricate missing context or installer-build evidence.
