# Final release convergence workflow

Use this workflow after the broad architecture is already established. It narrows execution toward release proof.

## 1. Refresh truth

Run the existing G0 grounding procedure. Record canonical repo/worktree/branch/HEAD/dirty state/remotes, active processes/resources, current Issue/PR control state, and applicable owner authorization. Historical SHA values in handoffs are navigation only.

## 2. Close model-selection integrity

Apply `covert-model-selection-integrity`. Do not proceed to live provider qualification while UI/persistence can mutate an exact target or hide unavailable state.

Exit condition: exact target identity survives UI/persistence/restart and negative cases without silent substitution.

## 3. Qualify provider/model route

When auth/spend authority exists, apply `covert-live-provider-qualification` to one exact high-priority route. Keep unsupported capabilities separate.

Exit condition: success, cancellation, timeout, provider error, cleanup, receipt, and restart/recovery are evidenced for the exact route.

If externally blocked, retain `BLOCKED/UNKNOWN` and continue independent local/package work.

## 4. Resolve local qualification gates

Use existing Resource Admission. Do not stop unrelated healthy user processes to manufacture headroom without authority. Qualify only when resource floors are genuinely satisfied.

## 5. Resolve cumulative Windows discrepancy

Apply `covert-windows-cumulative-stability` until the full declared suite is green or a documented environment/product limitation is established. Isolated passes cannot substitute for the cumulative result.

## 6. Build candidate and clean-room package

Create a candidate only after source-level required gates are stable. Build artifacts, hash them, and apply `covert-clean-room-release-acceptance` on a genuinely clean supported environment.

## 7. Whole-product packaged journeys

Exercise representative operator journeys through the package, including restart and failure recovery. Cover terminal/TUI/CLI and companion/integrations only to the declared release scope.

## 8. Reconcile documentation and support claims

README/install/use/troubleshooting/privacy/provider/platform/known-limitations statements must match the exact evidence matrix. Remove or qualify unsupported claims; do not hide visible incomplete capability to improve release status.

## 9. Freeze RC and issue release receipt

Apply `covert-rc-freeze-release-receipt`. Populate `RELEASE_CLAIM_TRACEABILITY_MATRIX.csv`. Bind all artifacts and claims to one candidate SHA. Run every mandatory affected gate.

## 10. Owner release decision

Present exact candidate SHA, artifact hashes, gate statuses, live provider/model matrix, supported platforms, known limitations, unresolved noncritical items, and publication actions requiring authority. Do not publish/tag/announce without applicable authorization.
