# THEME 03 — ORIGINAL / COLORFUL COVERT

Reference: `../01_REFERENCES/03_ORIGINAL_COLORFUL_OWNER_REFERENCE.jpg`

## Goal
Restore the expressive Covert identity that Luna previously captured: dark command center, strong purple/cyan/green/pink illumination, prominent Resident personality, model lineup and real resource status.

Do not "professionalize" this theme into Corporate. This theme is allowed to be bold.

## Baseline 1600x900
Header: 72 px.
Left navigation: 180 px.
Adjacent identity/art column: 170 px.
Center work surface: flexible.
Right stack: 310 px.
Status: 24 px.

## Header
Left:
- Covert sigil + `COVERT CODER`
- subtitle/small identity phrase

Center:
- `CODE | ANALYZE | BUILD | VERIFY | DEPLOY`
- secondary small discipline line
- optional world/system graphic only if it does not steal working space

Right:
- network/local/offline
- privacy/health
- compact window controls

## Left navigation
Preserve the reference's colorful functional categories:
Command Center, Resident, Projects, Editor, Terminal, Models, Skills, Memory, Verification, Security, Extensions, Settings.

Each category gets its own icon/accent but not arbitrary rainbow decoration. State meaning still follows shared semantics.

## Identity / Resident art column
Use an original Covert hooded hacker / Resident figure.
No recognizable franchise helmet/costume.

The figure's **eyes/visor are the theme's liveness instrument**:
- IDLE dim/static
- PLANNING cyan
- REASONING violet/magenta
- EXECUTING green
- COMPILING/TESTING bright green/cyan pulse
- DEBUGGING/WAITING amber
- STALE dim amber static
- FAILED/BLOCKED red static
- COMPLETE brief green confirmation then dim

When nothing is happening, the eyes must not continue pretending work is in progress.

## Center
Top mode tabs:
`Chat | Plan | Code | Review | Terminal | Browser`

Resident/chat is the dominant upper center:
- Resident identity/header
- readable message history
- quick action chips
- input composer
- model/mode selector
- send/stop control

Quick actions may include:
Analyze repository, Implement feature, Debug issue, Improve tests, Explain code, Security review, Optimize performance, Add to memory.

Lower center:
`Workspace | Files | Terminal | Tests | Output | System Map`
with terminal/workspace content visible.

## Right stack
1. Model Lineup — 250 px
2. System Resources — 210 px
3. Recent Activity — 260 px

### Model Lineup
Planner / Coder / Reviewer logical roles:
- exact selected model identity
- provider/local status
- readiness/qualification truth
- Manage action

### System Resources
Use one prominent ring + compact values:
- RAM / Commit / VRAM pressure should be visible
- CPU / Disk secondary
- real sparkline only when real history exists

### Recent Activity
Only real recent events:
- transport update
- tests
- file modifications
- security scan
- model load
etc.

## Visual language
Base `#0A0F1A`
Panel `#12182A`
Purple `#7C3AED`
Cyan `#22D3EE`
Green `#19E6A7`
Magenta `#FF4FD8`
Blue `#38BDF8`
Amber `#FFB547`

Use layered edge light and theme accents. Avoid glassy translucent soup and excessive bloom.

## Recovery instruction
Before rebuilding, search local Git history/worktrees/reflogs/stashes and archived frontend directories for Luna's prior implementation/assets. If found, recover selectively. If not found, reconstruct from the owner reference and this spec.

## Lock criteria
Owner must recognize the previous successful visual identity immediately. If it looks like a generic purple IDE, it fails.
